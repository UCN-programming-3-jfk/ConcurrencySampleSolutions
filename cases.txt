Update single row (e.g. editing a product or customer row)
- possible problem: Lost update
- solution: optimistic concurrency (without transaction) using UPDATE ... WHERE (comparison with old values using all column values or timestamp)
- examples:

UPDATE Customer SET Name = @NewName, Email = @NewEmail WHERE Id = @Id AND Name = @OldName AND Email = @OldEmail

UPDATE Customer SET Name = @Name, Email = @Email WHERE Id = @Id AND Timestamp = @oldTimestamp

Update multiple rows
- possible problem: Lost update (insufficient stock) (create order from shopping cart)
- solution : 	use transaction
				read expected number of rows affected
				perform update
				compare expected vs actual rows affected
				commit if equal
- example: (user checks three todo items as done, and clicks update)
	C# start transaction - isolation level repeatable read
	C# int rowsToUpdate = command.ExecuteScalar(...
	SQL SELECT COUNT(*) FROM Tasks WHERE UserId = @UserId and IsDone = false AND TaskId IN (3,7,9,12)
	C# int rowsAffected = command.ExecuteNonQuery(...
	SQL UPDATE Tasks SET IsDone = true WHERE UserId = @UserId and IsDone = false AND TaskId IN (3,7,9,12)
	C# if(rowsToUpdate == rowsAffected) transaction.Commit();

- possible problem: unfinished actions (e.g. money withdrawn from one account but not deposited in another)
- solution: use simple transaction w. repeatable read
- example: (check balance in account A, if balance is positive withdraw amount, deposit in account B) commit
